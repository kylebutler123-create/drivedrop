# Signed-in mobile public pages

The approved premium homepage was restricted to `role-guest`: signed-in visitors received the same `/` route, but CSS hid the new homepage and exposed the legacy content. This was a presentation condition, not an authentication redirect or service-worker cache.

The public mobile navigation and footer render for every session on the homepage, How it works, For customers, For transporters, About, Help, Contact, Terms, Privacy, Get quotes, sign-in, registration and password-recovery routes. Public mobile styling follows that navigation's presence instead of the user's role. Signed-in visitors see “My account” and a menu link to their existing role-specific dashboard; guest sign-in and registration links remain unchanged. The public header replaces the mobile workspace header and bottom navigation only while this public navigation is present. Navigating back to an account screen restores its existing navigation.

The premium photography, logo dimensions and homepage content are retained. Desktop presentation, session handling, `/app` launch redirects, account authorization and APIs are unchanged. Generic account button and input styles are excluded from the public pages so their typography, spacing and borders stay consistent. Private account routes keep their existing presentation. The existing customer redirect from Get quotes to the customer workspace is retained.

Verification uses isolated fixture sessions for guests, customers, transporters and admins, with API traffic intercepted locally. Checks cover all 16 public route variants (including the six auth screens), mobile visibility and content styling, shared header/footer and logo sizing, account links, client navigation, browser back/refresh, guest auth regression and unchanged desktop rendering. Help search, how-it-works tabs, legal links and password visibility use their original handlers. No live accounts or records are modified.
