# Mobile expanded delivery cards

Matches the approved expanded-card preview below 1024px. The existing mobile summary continues to show the vehicle, route, collection schedule, progress and contact actions. Expanded cards show four additional vehicle facts, one payment panel, transporter next actions, and collapsible evidence. Customer cards omit the separate Delivery history disclosure, as approved.

`MobileDeliveryDetails.tsx` contains presentation components. Amounts, payment status, payout status and refund adjustments come from the existing role-scoped booking response. No pricing, payment or eligibility rules change. Signed collection/delivery reports use the same authorised evidence URLs and retain timestamps, condition notes, signatures and location information. The existing upload, proof, confirmation, dispute, cancellation, review and receipt controls remain mounted with their original handlers.

The older identity/route/payment nodes remain available to the desktop layout and selector-based enhancers, but are hidden on mobile where their information is already shown. Both account types hide the separate expanded history panel at the user's request; the compact progress indicator remains visible, and dated updates and notes are preserved for desktop. On customer cards, Collection & delivery evidence follows the payment section directly. The sibling action panel, disputes and collection/delivery evidence stay available. Messages remain accessible through the summary's existing conversation link. All new styles are scoped to the mobile breakpoint and customer/transporter roles.

The transporter mobile summary uses the approved navy details button (`#071c43`) with white text and arrow. Both customer and transporter delivery cards use the same blue Message circle (`#2563eb`) and green Call circle (`#16a34a`), with white glyphs, in compact and expanded cards. Customer details buttons retain their orange style. Collection and delivery action buttons retain their orange style and use the same 16px font size and bold (700) weight as the transporter details button. Contact labels, sizes, icons, links and behaviour are unchanged. These overrides do not affect job/quote buttons or desktop.

The customer mobile “Confirm vehicle received” button also uses 16px text with a bold (700) weight, matching “Close delivery details”. The same typography is retained while confirming receipt; confirmation eligibility and behaviour are unchanged.

The real-map design reference uses a sample Manchester–Birmingham route. It is not wired into booking cards: jobs currently store address strings, not collection/delivery coordinates or route geometry. A geocoding and routing provider needs to be connected before the real map can represent each booking. Do not embed the sample map as actual delivery data. The existing proof-of-delivery location map remains separate and unchanged.

Validation uses isolated customer/transporter fixtures and intercepted API requests: 320/390/430/768px layouts, disclosure and collapse behaviour, dispute drafting/cancellation, collection and delivery forms, status drafting, cancellation prompt, delivered confirmation, signed evidence, refunds, completed receipts/reviews, cancelled bookings, active disputes and missing payment data. No live payment, booking, message or evidence mutations are performed. TypeScript and the production build are checked before preview publication.
