# Mobile account details

Applies the approved account-page design below 1024px to Personal details, Business & photos, Verification & insurance, and Stripe payout setup. The installed home-screen app and mobile website share these components. Navy identity panels, orange actions, white cards and the existing white bottom navigation match the account and messages screens.

Personal and business summaries use existing account data. A shared editing context opens the original account editor without duplicating saves or losing its draft. Success messages remain visible after saving. Photo rows retain the original file inputs, crop/position dialog, uploads and remove actions. Empty photo slots use initials or vehicle icons, never sample imagery.

Verification uses the approved three states: both forms when neither document exists, one current document card plus the remaining form after either first upload, and two current document cards after both uploads. Each type's form closes immediately after a successful upload. Upload replacement opens only that type's existing form; cancellation closes it again, and failed uploads leave it available for retry. Initial loading does not briefly expose empty forms for an existing account.

The current licence and insurance cards use the newest records by creation time and show actual status, expiry and authorised document links. Earlier records remain available in a collapsed Previous documents section and in the existing desktop/admin review workflows; nothing is deleted. Replacements update the current card rather than adding duplicate current cards. Insurance warnings, review notes, business editing and submission rules remain in place. Account navigation uses client-side links to preserve the app shell, and failed document loads have a retry action.

Stripe setup retains its original status request, dashboard/onboarding actions, disabled states, requirement and bank-payout warnings, refresh and error handling. The mobile summary reflects the current connection and environment; no bank details, balances or approved states are invented. No payment configuration, API routes, authentication or database code changes.

Validation: TypeScript and production builds passed. The latest verification update passed 23 isolated browser checks covering both upload orders, reload persistence, one card per document type, replacement/cancel/switch behaviour, failed uploads, successful uploads followed by failed refresh, repeated-submit protection, newest-record selection, review submission, rejected/expired documents, business setup, loading and retry. Layouts were checked at 320, 390, 430 and 768px. Production desktop comparisons at 1440px showed zero changed pixels for transporter account, customer account and verification. No browser runtime errors occurred. All browser mutations were intercepted locally; live accounts, uploads, payments and messages were not modified by QA.
